# Contributing

Thanks for your interest in improving <package-name>!
This guide gets you set up and explains how the project is put together.
If anything here is unclear, opening an issue to ask is welcome.

## Getting set up

Use Node.js 22.18 or newer in the 22.x line, or 24.11 or newer in the 24.x line.
Then install the dependencies:

```sh
<pm> install
```

Commit the lockfile generated by your package manager. CI uses it to select the installer. Dependabot groups package dependency changes and GitHub Actions changes into weekly pull requests. Review TypeScript and `@types/node` major upgrades manually. Dependabot can propose minor and patch updates within the supported majors. When upgrading either major manually, update the matching ignore range in .github/dependabot.yml.

## Scripts

| Command | What it does |
| --- | --- |
| `<pm> run build` | Bundle ESM/CJS + type declarations with tsdown |
| `<pm> run test` | Run the tests once with vitest (`<pm> run test:watch` to keep them running) |
| `<pm> run test:coverage` | Run the tests with a coverage report |
| `<pm> run typecheck` | Type-check with `tsc --noEmit` |
| `<pm> run format` | Format the code, writing the fixes (Prettier) |
| `<pm> run format:check` | Check formatting without writing (Prettier) |
| `<pm> run lint` | Lint the code without writing fixes (ESLint) |
| `<pm> run lint:fix` | Lint the code, writing the fixes (ESLint) |
| `<pm> run check` | Format and lint, writing the fixes (Prettier + ESLint) |
| `<pm> run ci` | The same checks without writing — what CI runs |

Before opening a pull request, make sure the full set passes:

```sh
<pm> run ci && <pm> run typecheck && <pm> run test && <pm> run build
```

## Conventions

- **Formatting is Prettier** (default settings, no overrides) and **linting is ESLint**
  (`eslint.config.js` — `typescript-eslint`'s recommended rules, with `eslint-config-prettier`
  disabling any ESLint rule that would conflict with Prettier's formatting).
  Running `<pm> run check` before you commit handles both.
- **Tests live next to the code** as `*.test.ts` and run with vitest.
- **Comments and docs are in English** and kept brief.
- **Type-only imports use `import type`** (`verbatimModuleSyntax` is on).

## Pull requests

Keep each change focused and add tests for any new behaviour.

## Releasing (maintainers)

Run the `release` workflow from `main`. Pass a bump (`patch`, `minor`, `major`, `prerelease`) or an explicit version such as `1.2.0` or `v1.2.0-rc.0`. A `minor` bump with `preid=rc` starts the next minor prerelease at `rc.0`. An abbreviated version such as `1.2.0-rc` picks the next number in that series.

The workflow checks and builds the selected version, pushes the version commit and tag together, publishes to npm through trusted publishing, then creates the GitHub Release. Configure the trusted publisher on npmjs.com under **Settings → Publishing access → Trusted publishers → GitHub**. Set the workflow file to `release.yml`.

To resume after the tag was pushed, dispatch the workflow with the latest tag as an explicit version, including the prerelease number if there is one. The workflow uses the tagged commit, skips a version already on npm, and leaves an existing GitHub Release in place. By default, npm uses `latest` for stable releases and the prerelease identifier for prereleases. Pass `dist_tag` to override the npm dist-tag when needed.
